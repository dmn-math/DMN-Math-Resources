DMN MATHEMATICS · GITHUB EDITION

Your website, your accounts.

The finished teacher dashboard and student page run on GitHub Pages. Supabase handles teacher login; a Cloudflare Worker, D1 and R2 handle shared content and uploaded files. No AI API or ChatGPT account is needed to use the finished site.

Uploading the website is one step. Connecting the backend is a separate one-time step. Until connected, the website offers a labelled local preview. Its changes stay on that browser.

1. Upload the website to your GitHub repository

  1. Extract DMN-Math-GitHub.zip.
  2. Inside UPLOAD_TO_GITHUB, copy the entire math-workspace folder into your existing DMN-Math-Resources repository. Keep your current index and reflection pages.
  3. Use GitHub Desktop to commit and push the folder. This is easier than adding hundreds of cropped images through the web uploader. Upload the extracted folder, not the ZIP.
  4. Allow the existing GitHub Pages deployment to finish.

The teacher page starts with the create-paper button and current reflection papers.

2. Set up teacher login in your Supabase account

  1. Create a Supabase project that you own. Keep your database password private.
  2. Under Authentication, enable email/password login and keep email confirmation enabled.
  3. Set the site URL to https://dmn-math.github.io/DMN-Math-Resources/math-workspace/index.html. Add that exact URL and https://dmn-math.github.io/DMN-Math-Resources/math-workspace/index.html?recovery=1 to the allowed redirect URLs.
  4. Create your own owner login account. You can use Authentication → Users → Add user in your Supabase dashboard, set a strong password and confirm that user's email there. Use the same email later for OWNER_EMAIL.
  5. Copy the project URL and public publishable key from the project's connection/API settings. A public anon key also works. Do not copy the secret or service-role key.
  6. For teachers to receive confirmation and password reset emails, configure your own SMTP provider in Supabase. The default email service has restrictions. Alternatively create and confirm teacher accounts yourself in Supabase, then give them their account details through your normal private channel.

Teachers create an account through the site's sign-in page only if you enable sign-ups. A confirmed account still has no workspace access until you add its email in Settings.

3. Deploy the shared backend in your Cloudflare account

Install Node.js 22.13 or newer. Open a terminal in the extracted SOURCE folder. Run:

npm install
npx wrangler login
npx wrangler d1 create dmn-math-db
npx wrangler r2 bucket create dmn-math-files

Enable R2 in your Cloudflare account if prompted. Save the database ID reported by the D1 command.

Open SOURCE/backend/wrangler.jsonc and replace these fields:

FieldValue
OWNER_EMAILYour confirmed owner login email
SUPABASE_URLYour Supabase project URL
SUPABASE_PUBLISHABLE_KEYYour public publishable/anon key
database_idThe ID from the D1 create command
ALLOWED_ORIGINSKeep https://dmn-math.github.io for your current GitHub site. For another domain, enter its origin without a path.

Apply all three migrations (schema, initial question bank and anonymous class results), then deploy:

npm run backend:migrate
npm run backend:deploy

Copy the Worker address printed at the end, for example https://dmn-math-api.YOUR-SUBDOMAIN.workers.dev. Open https://YOUR-WORKER-ADDRESS/api/health: it should report ready: true. This checks configured bindings; your first teacher login below verifies access to the database and login service.

4. Connect the website to your backend

Edit math-workspace/workspace-config.js in your GitHub repository:

window.DMN_CONFIG = {
  apiUrl: "https://dmn-math-api.YOUR-SUBDOMAIN.workers.dev",
  supabaseUrl: "https://YOUR-PROJECT.supabase.co",
  supabasePublishableKey: "YOUR_PUBLIC_PUBLISHABLE_KEY"
};

Commit and push this file. After GitHub Pages redeploys, reload the teacher page. You will see teacher sign-in instead of the local preview.

Use the same Supabase project URL and public key in the website and backend. Leave apiUrl without /api at the end. Never put account passwords, a Cloudflare token, or a Supabase secret/service-role key into the website.

If your school filters internet access, it must also allow the Worker and Supabase project addresses. Keeping the GitHub webpage address does not automatically allow those backend connections.

5. Verify the shared workflow

  1. Sign in using your confirmed owner email/password. Confirm the current E-Math and A-Math papers load.
  2. In Settings → Teacher access, add a second teacher email as Editor. Have that teacher use a confirmed account for the same Supabase project.
  3. Have the teacher create a practice-source paper, upload a PDF, crop one complete question, add its marks, TOS SIO and AO. Review the details and publish it; there is no per-part review checkbox.
  4. Open the question bank from your own device. The published question should appear after refreshing; open teacher dashboards also check for updates every 30 seconds when no unsaved paper edits are present.
  5. Create a class for a published reflection paper, copy its class link and open it in a private browser window. Complete a test reflection and send it using only the shared class code. No student name, assigned code or login is needed.
  6. Confirm the anonymous class count, averages and learning gaps appear only for the owner and that class's assigned teachers. There is no individual result view. Download a personalised PDF and check its screenshots and answers.
  7. Remove the test teacher or test content when finished. Approve the teachers who will use the site.

Updating an existing installation

Keep your configured workspace-config.js. Apply 0003_anonymous_class_results.sql using npm run backend:migrate, then redeploy the updated backend and upload the new website files. The migration preserves earlier class analyses as anonymous contributions and removes the old assigned codes, identifying IDs and raw entries. The updated frontend and backend must be installed together.

Using the website afterwards

Teachers upload, crop, tag and publish through the dashboard. Content is stored online, so routine question changes do not require replacing HTML files. Website design/code changes require a new build and upload. Students get the latest published paper on their next load; teacher dashboards check for shared updates every 30 seconds.

Uploaded PDFs are available for manual cropping. Question boundaries, marks, SIOs and AO tags are reviewed by a teacher; this version does not perform automatic AI extraction. The bank shows unfilled SIOs so you can add suitable, authorised questions over time.

Practices are suggested automatically, and teachers can replace any suggestion. Publish reflection shows an inline confirmation and a copyable student link. Share a class link from Class reflections when you want to receive anonymous class summaries. Students retain their own private analysis and PDF on their device. A private browser receipt lets them correct their submission from that same browser.

Before the backend is connected, the teacher page opens directly in local preview, which can be used to inspect the workflow and generate student PDFs. Preview edits stay on that browser and are not automatically migrated online. Connect first before adding your production papers.
